# AGAYO v13.3 — билеты, возвраты, сканер, Яндекс Диск, checkout и hero

Это overlay-архив поверх текущего `main`. Новая SQL-миграция **не нужна**.

## Что сделано

### 1. Билеты в админке
- В разделе **Билеты** автоматически показываются все доступные администратору билеты, без обязательного поиска.
- Список имеет собственную прокрутку и не раздувает страницу.
- Поиск работает по номеру билета, заказу, владельцу, email, телефону, AGAYO ID и событию.
- Есть кнопки «Все билеты» и «Обновить».
- Контролёры не получают финансовые данные: сумма и `yookassa_payment_id` скрываются сервером, если нет `view_revenue`.

### 2. Операции с билетом
- **Отменить билет** — делает действительный билет недействительным, но НЕ возвращает деньги.
- **Восстановить** — возвращает вручную отменённый билет в `valid`, если заказ всё ещё `paid`.
- **Сбросить проход** — переводит ошибочно отсканированный `used` обратно в `valid` и пересчитывает лояльность.
- Все операции проходят через серверные permission checks и пишутся в `admin_audit_log`.

### 3. Возврат денег через YooKassa
- Добавлен реальный `POST /v3/refunds` через YooKassa API.
- Кнопка **Вернуть оплату** доступна владельцу/администратору с `view_revenue`.
- Возврат делается **на весь заказ**, а не на один билет. Если в заказе несколько билетов, UI отдельно предупреждает об этом.
- После полного возврата заказ становится `refunded`, все его билеты — `refunded`.
- Webhook `refund.succeeded` остаётся резервным каналом синхронизации.
- Используется стабильный Idempotence-Key, поэтому повтор клика/сетевой retry не должен создавать второй одинаковый возврат.
- Если YooKassa уже видит полный возврат, но БД AGAYO не успела обновиться, админ-действие синхронизирует локальное состояние без нового возврата.
- Частичный возврат из этой панели намеренно заблокирован. Для корректного частичного возврата нужно сначала детализировать позиции чека по отдельным билетам.

Для «Чеков от YooKassa» при полном возврате `receipt` в запросе возврата не нужен: YooKassa использует данные исходного платежа. До боевого запуска всё равно отдельно проверяем фискализацию и реальные параметры чека.

### 4. Сканер
- После каждого QR появляется модальное окно со статусом:
  - проход разрешён;
  - уже использован;
  - билет недействителен;
  - билет не найден.
- Камера остаётся включённой, но следующий QR **не обрабатывается**, пока сотрудник не нажмёт `ОК · СКАНИРОВАТЬ ДАЛЬШЕ`.
- После ОК блокировка снимается и можно сразу сканировать следующий билет.

### 5. Фото
- Обычная мультизагрузка файлов с устройства остаётся без изменений.
- Добавлен импорт по **публичной ссылке Яндекс Диска**.
- Можно вставить ссылку на отдельный файл или публичную папку.
- Поддерживаемые изображения копируются в Vercel Blob AGAYO, после чего добавляются в `media_photos`.
- Таким образом, галерея после импорта не зависит от того, останется ли публичная ссылка Яндекс Диска активной.
- Ограничение одного изображения остаётся 16 МБ; за один импорт — до 250 изображений.
- Если владелец Яндекс Диска запретил скачивание или сработал лимит публичных скачиваний, импорт покажет ошибку Яндекса.

### 6. Страница проверки оплаты
Аудит показал, что серверная часть уже сделана правильно: при `pending` AGAYO сам запрашивает авторитетный статус у YooKassa, а при `paid` безопасно повторяет только неуспешную доставку письма.

Исправлены два UX-края:
- URL без `?order=...` больше не зависает навсегда на «Платёж проверяется»;
- автоматическая проверка больше не крутится бесконечно: примерно через минуту появляется ручная кнопка «Проверить ещё раз».

Также отдельно показывается случай ошибки доставки email: билет при этом остаётся доступен в AGAYO ID.

### 7. Контраст кнопок
- Для залитых бордовых/акцентных кнопок принудительно закреплён светлый текст.
- Event theme больше не может перекрасить акцентную кнопку так, чтобы фон и текст слились.

### 8. Афиша на первом экране главной
- На desktop афиша занимает правую часть hero.
- В сторону текста слева уходит длинный тёмный градиент в фирменный фон AGAYO.
- На телефоне изображение остаётся полноэкранным, но смещено вправо и затемнено слева/снизу для читаемости текста.

## После загрузки в GitHub

1. Дождаться зелёного Vercel deployment.
2. Открыть `/admin` → **Билеты**: список должен загрузиться сразу.
3. На ТЕСТОВОМ магазине YooKassa провести ещё одну тестовую покупку.
4. Через админку нажать **Вернуть оплату** и подтвердить.
5. Проверить:
   - заказ → `refunded`;
   - билет → `refunded`;
   - повторное сканирование не пускает;
   - тестовый возврат появился в YooKassa.
6. Проверить «Отменить билет» на другом тестовом билете: деньги возвращаться не должны.
7. Проверить сканер: после каждого QR обязательно должен появляться экран статуса с ОК.
8. В «Фото и отзывы» проверить:
   - несколько файлов с компьютера;
   - публичную ссылку Яндекс Диска.
9. Открыть обычный успешный checkout и отдельно `/checkout/success` без `order`.
10. Проверить главную на desktop + телефоне и пройтись по залитым кнопкам.

## Важно перед боевыми продажами

Это не завершает этап фискализации. До `PAYMENTS_ENABLED=1` с БОЕВЫМИ ключами отдельно настраиваем и проверяем «Чеки от YooKassa», VAT/payment_mode/payment_subject и полный production QA.
