# AGAYO v13.4 — возвраты, НПД, фото, уровни и mobile QA

Эта версия ставится поверх v13.3. GitHub автоматически не менялся — архив подготовлен для ручной загрузки.

## 1. Сначала база данных

До загрузки нового кода выполни в Neon целиком:

`db/011_refunds_loyalty_visuals_npd.sql`

Миграция:
- переводит `orders.refunded_amount` на точные суммы с копейками;
- добавляет отдельные возвраты по билетам;
- добавляет статусы чеков НПД;
- добавляет ключ источника фото для безопасного продолжения импорта Яндекс Диска;
- добавляет визуальные настройки уровней AGAYO ID.

## 2. Настройки YooKassa / НПД

Для текущего ИП на НПД:

```env
YOOKASSA_RECEIPT_REQUIRED=0
FISCALIZATION_CONFIRMED=0
```

Не заполняй для текущей схемы НПД:

```env
YOOKASSA_VAT_CODE=
YOOKASSA_PAYMENT_MODE=
YOOKASSA_PAYMENT_SUBJECT=
```

`FISCALIZATION_CONFIRMED=1` ставим только после реального теста процесса «оплата -> чек в Мой налог -> частичный возврат -> корректировка/аннулирование чека». Это только внутренний флаг готовности AGAYO, а не включение кассовых чеков YooKassa.

## 3. Что изменилось

### Частичный возврат одного билета
AGAYO сам считает процент от даты мероприятия:
- 10 дней и более — 100%;
- от 5 до 10 дней — 50%;
- от 3 до 5 дней — 30%;
- менее 3 дней — 0% по заданной политике.

Сумма считается от фактически оплаченной доли конкретного билета с учетом скидки заказа. После денежного возврата билет становится недействительным. Полный возврат остатка всего заказа остается в «Доп. действия».

Важно: публичную оферту я намеренно не переписывал под правило 100/50/30/0. Такое правило прямо закреплено в ст. 52.1 Закона о культуре для организаций исполнительских искусств и музеев; применимость именно к формату AGAYO нужно подтвердить юридически до публикации правила как безусловного ограничения прав покупателя.

### НПД / Мой налог
После успешной оплаты заказ получает статус «Нужен чек НПД». В админке можно сохранить ссылку или номер чека. AGAYO отправит покупателю письмо с реквизитами чека.

После частичного возврата ранее выданный чек помечается как требующий переоформления. После полного возврата — как требующий аннулирования. Прямого подключения к закрытому API ФНС в этой версии нет: автоматизация через ФНС требует работы через уполномоченный канал/партнера, поэтому сейчас система контролирует и документирует ручной процесс «Мой налог».

### Билеты в админке
- полный прокручиваемый список;
- поиск по билету, заказу, имени, email, телефону, AGAYO ID, категории и событию;
- отмена/восстановление билета;
- сброс случайного прохода;
- частичный возврат конкретного билета;
- полный возврат оставшейся суммы заказа;
- контроль статуса НПД-чека.

### Сканер
После QR появляется модальное окно. Теперь отдельно и крупно показывается категория билета. Следующий QR не принимается до кнопки «ОК · СКАНИРОВАТЬ ДАЛЬШЕ».

### Фотографии
Локальная массовая загрузка больше не обрывает всю очередь из-за одного файла: неудавшиеся файлы остаются в очереди, после восстановления связи можно нажать «Продолжить оставшиеся».

Яндекс Диск:
- прогресс хранится в `localStorage` браузера;
- после ошибки/закрытия вкладки можно продолжить;
- серверный `source_key` не дает повторно создать уже импортированные фото;
- добавлена кнопка удаления всех фотографий выбранного мероприятия.

### AGAYO ID
Для каждого уровня лояльности администратор выбирает:
- собственную цветовую палитру; или
- загруженное изображение-фон.

Настройка находится в админке в разделе покупателей/лояльности. Карточка AGAYO ID пользователя автоматически берет визуал его текущего уровня.

### Билеты в профиле
Карточки активных, использованных и архивных билетов теперь наследуют цветовую палитру соответствующего мероприятия.

### Письмо после покупки
В письме теперь находится сам билет: данные события, владелец, категория, ID и QR-код. Дополнительно прикладываются QR PNG и файл полного билета SVG. Ссылка остается только запасным способом открыть актуальный статус.

### Мобильная версия и контраст
- запрещено ломать длинные слова в заголовках события посередине слова;
- мобильный размер крупных заголовков уменьшен и привязан к ширине экрана;
- «HALLOWEEN» и подобные слова должны помещаться целиком;
- светлый блок события всегда использует темный текст;
- ссылка «Правила мероприятия» больше не может стать белой на светлом фоне;
- темные/event-colored блоки принудительно используют светлый текст;
- залитые кнопки имеют контрастный светлый текст.

## 4. Порядок проверки

1. Neon: выполнить `011_refunds_loyalty_visuals_npd.sql`.
2. Загрузить файлы v13.4 в GitHub поверх v13.3.
3. Дождаться зеленого Vercel deployment.
4. Открыть админку -> Настройки: PostgreSQL должен стать ГОТОВО.
5. Купить тестовый билет через тестовый магазин YooKassa.
6. Проверить письмо: полный билет и QR должны быть прямо в письме, плюс вложение.
7. Создать чек в «Мой налог», вставить ссылку/номер в админке и подтвердить.
8. Проверить, что покупателю ушло письмо с чеком.
9. Проверить возвраты на разных тестовых датах мероприятия: 100%, 50%, 30%, 0%.
10. После частичного возврата проверить статус НПД «аннулировать и выдать новый».
11. Отсканировать QR: в окне должны быть имя + крупная категория билета.
12. Проверить локальную загрузку нескольких фото, оборвать соединение и продолжить оставшиеся.
13. Проверить импорт одной и той же папки Яндекс Диска дважды — дублей быть не должно.
14. Проверить «Удалить все фото этого мероприятия» только на тестовом событии.
15. Настроить визуал каждого уровня и проверить профиль пользователя.
16. На iPhone/Android проверить длинный заголовок события, светлый блок, кнопки и профиль.
17. Только после полного теста НПД-процесса поставить `FISCALIZATION_CONFIRMED=1`.

## Проверка исходников
Все TS/TSX-файлы v13.4 прогнаны через TypeScript parser: синтаксических диагностик — 0. Полный production build нужно подтвердить зеленым Vercel deployment, потому что локальная рабочая среда не содержит установленных npm-зависимостей проекта.
