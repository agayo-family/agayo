# Подключение Telegram к доставке билетов AGAYO

Подготовлено 16 октября 2026 года. Код интеграции готовится в этом релизе; реальный бот, токен и webhook автоматически не создавались. Не присылайте токены в чат и не размещайте их в репозитории.

## Что получит покупатель

1. Покупатель входит в свой AGAYO ID на сайте.
2. В настройках профиля нажимает «Подключить Telegram».
3. Открывает выданную сайтом ссылку бота и нажимает «Начать».
4. Сайт привязывает личный чат к этому аккаунту и переключает новые билеты на Telegram.
5. После оплаты приходит файл PNG с действующим QR, сведения о событии, категория, номер билета и кнопка актуального билета на сайте. Файл формируется в памяти, без загрузки в Blob.

Email остаётся необходимым для входа, чеков и резервного канала. Старые билеты автоматически не пересылаются при подключении. Покупатель может переключить доставку обратно на email или отвязать бота. Все купленные билеты остаются в профиле сайта независимо от канала доставки.

## Подготовка организатором

1. Откройте официальный [@BotFather](https://t.me/BotFather) в Telegram. Выполните `/newbot`, укажите имя и свободный username, заканчивающийся на `bot`.
2. Сохраните выданный токен в менеджере паролей. Для бота рекомендуется отключить добавление в группы через `/setjoingroups`: сайт всё равно принимает привязку только из личного чата.
3. Примените миграцию `db/017_telegram_delivery.sql` к рабочей БД после существующих миграций. Она добавляет предпочтение доставки, одноразовые ссылки и отдельный журнал фактических доставок Telegram. Миграцию следует предварительно проверить на копии БД; исходящие запросы к Telegram она не делает.
4. В защищённых серверных переменных хостинга добавьте:

| Переменная | Значение |
|---|---|
| `TELEGRAM_BOT_TOKEN` | Токен BotFather |
| `TELEGRAM_BOT_USERNAME` | Username без `@` |
| `TELEGRAM_WEBHOOK_SECRET` | Случайная строка из 32–256 символов `A–Z`, `a–z`, `0–9`, `_`, `-` |
| `NEXT_PUBLIC_SITE_URL` | `https://www.agayo.ru` |

Три переменные Telegram не должны иметь префикса `NEXT_PUBLIC_`. Не добавляйте production-токен в Preview/Development: иначе тестовая копия сможет послать настоящий билет. После сохранения переменных переразверните production-версию.

5. Зарегистрируйте webhook у Telegram: метод `setWebhook`, URL `https://www.agayo.ru/api/telegram/webhook`, тот же `secret_token`, `allowed_updates=["message"]`. У одного бота один активный webhook; при переезде его нужно обновить только если меняется публичный URL. При сохранении домена URL останется прежним.

Этот пример выполняется **вручную на доверенном компьютере**, а не в чате или онлайн-сервисе. Он просит секреты скрытым вводом и не печатает URL с токеном:

```powershell
$agayoBotSecure = Read-Host 'Токен BotFather' -AsSecureString
$agayoWebhookSecure = Read-Host 'TELEGRAM_WEBHOOK_SECRET' -AsSecureString
$agayoBotToken = [System.Net.NetworkCredential]::new('', $agayoBotSecure).Password
$agayoWebhookSecret = [System.Net.NetworkCredential]::new('', $agayoWebhookSecure).Password
$agayoWebhookBody = @{
  url = 'https://www.agayo.ru/api/telegram/webhook'
  secret_token = $agayoWebhookSecret
  allowed_updates = '["message"]'
  max_connections = '5'
}
try {
  $agayoWebhookResult = Invoke-RestMethod -Method Post -Uri ('https://api.telegram.org/bot' + $agayoBotToken + '/setWebhook') -Body $agayoWebhookBody -ErrorAction Stop
  $agayoWebhookResult | Select-Object ok, description
} catch {
  Write-Output 'Не удалось установить webhook. Проверьте токен и настройки, не публикуйте полный текст ошибки: он может содержать токен.'
} finally {
  Remove-Variable agayoBotToken, agayoWebhookSecret, agayoWebhookBody -ErrorAction SilentlyContinue
}
```

6. Проверьте webhook методом `getWebhookInfo`: URL должен совпадать с адресом выше, `last_error_message` не должен показывать продолжающуюся ошибку. Ответ проверяется локально; не публикуйте полный вывод с настройками.
7. Войдите в свой тестовый аккаунт AGAYO, привяжите Telegram через профиль и выпустите один согласованный бесплатный тестовый билет. Проверьте QR, файл, категорию, кнопку и отсутствие дублирования при повторе события оплаты. Не проводите реальную оплату или массовую рассылку ради этой проверки.
8. Переключите аккаунт на email и проверьте доставку одного отдельного тестового билета. Затем заблокируйте бота тестовым аккаунтом: явный отказ Telegram должен перевести этот билет на email.

## Ограничения и восстановление

- Telegram не принимает idempotency key для `sendDocument`. Сайт сначала записывает долговечный маркер `sending` в БД, затем отправляет файл вне SQL-транзакции. Подтверждённый `sent` повторно не отправляется.
- Явный отказ API, например заблокированный бот, записывается как `failed` и допускает резервную отправку по email с прежним стабильным ключом Resend.
- При таймауте, потере ответа или ошибке сервера неизвестно, получил ли Telegram файл. Такой билет помечается `uncertain` и **не отправляется автоматически второй раз**. Требуется проверка оператором с покупателем. До этого сам билет доступен в профиле AGAYO. Зависший `sending` старше двух минут при следующей попытке также переводится в `uncertain`.
- Фактический канал, chat ID, статус и message ID находятся в `telegram_ticket_deliveries`. Существующий `ticket_deliveries` используется как общий маркер завершения старой очереди: его историческое название канала `email` само по себе не доказывает фактическую отправку письма после включения маршрутизации.
- Связка требует согласованного текущего владельца билета и email аккаунта. Нельзя подставить email другого аккаунта и получить чужой билет в его Telegram.
- Ссылка привязки одноразовая, действует 10 минут, в БД хранится только её хеш. Новый выпуск ссылки и отвязка отзывают предыдущие ссылки. Один личный Telegram-чат нельзя одновременно привязать к двум аккаунтам AGAYO.
- Необходим мониторинг `sending`/`uncertain` и существующей очереди доставки. Независимый фоновый обработчик повторов остаётся отдельной задачей надёжности агрегатора; webhook оплаты не является такой очередью.
- При смене токена через BotFather обновите серверную переменную и webhook. Сохранённые привязки относятся к chat ID: новый бот требует повторного согласия пользователя через «Начать»; новый бот автоматически писать прежним пользователям не сможет.

Справочные первоисточники: [deep links](https://core.telegram.org/bots/features#deep-linking), [setWebhook](https://core.telegram.org/bots/api#setwebhook), [sendDocument](https://core.telegram.org/bots/api#senddocument), [BotFather](https://core.telegram.org/bots/features#botfather).
