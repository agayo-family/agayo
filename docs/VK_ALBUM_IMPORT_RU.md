# Импорт фотографий из ВК

В админке открой «Фото», выбери мероприятие и вставь ссылку на альбом, например `https://vk.ru/album-241505282_311782197`. Кнопка запускает импорт по 25 фотографий в очереди. Файлы переносятся по одному в Vercel Blob и сохраняются в галерее выбранного мероприятия.

Понадобятся серверные переменные `VK_ACCESS_TOKEN` и `BLOB_READ_WRITE_TOKEN` (либо существующий токен Blob с префиксом проекта). Токен ВК должен приниматься методами `photos.get` и `photos.getById` версии API 5.199 и иметь доступ к фотографиям выбранного альбома. Токен не отправляется в браузер, не сохраняется в очереди и не попадает в сообщения об ошибках. Для сохранения результатов нужна уже используемая миграция `db/011_refunds_loyalty_visuals_npd.sql` с уникальным `media_photos.source_key`.

Требования к конкретному типу токена и выдаче разрешения `photos` необходимо сверить с актуальными официальными правилами ВК при подключении. При разработке 15.10.2026 официальная документация не была доступна в рабочем окружении; работа без токена не предполагается. Если ВК отклоняет токен, закрывает альбом, ограничивает частоту запросов или требует CAPTCHA, импорт останавливается с понятным сообщением. Проверки ВК автоматически не обходятся.

«Пауза» завершает текущую фотографию и сохраняет очередь в этом браузере. После перезагрузки страницы доступно «Продолжить импорт». При обрыве соединения результат уже завершённой сервером загрузки определяется по стабильному ключу фотографии и мероприятия: повтор не создаёт дубликат. Для другого мероприятия эта же фотография может быть импортирована отдельно. Смена браузера требует нового запуска со ссылки; ранее добавленные фотографии будут пропущены. При изменении состава альбома во время импорта лучше повторить запуск со ссылки — дубликаты также пропускаются.

Файлы принимаются только с HTTPS CDN ВК `*.userapi.com` / `*.vkuserphoto.ru`. Каждое перенаправление проверяется. Ограничены время загрузки и размер 16 МБ; проверяются MIME и сигнатура JPG, PNG, WEBP, GIF или AVIF. Произвольные ссылки на изображения сервер не принимает. Перед записью повторно проверяются доступ сотрудника и существование мероприятия. Запись фотографии и запись аудита проходят в одной транзакции. После неясного результата COMMIT отдельная транзакция с тем же блокирующим ключом проверяет, используется ли адрес файла в БД: подтверждённо неиспользуемый Blob удаляется, при недоступной БД сохраняется. Поэтому при сбое очистки могут остаться лишние файлы, а уже записанная фотография не теряет свой файл. При переносе фотографии в другое мероприятие ключ импорта очищается, чтобы повтор исходного альбома не возвращал фотографию из чужого события.

Неудавшиеся отдельные фотографии видны в отчёте и могут быть повторены. Остановка из-за токена, доступа, лимита или связи сохраняет позицию, а не пропускает всю оставшуюся очередь. Большой альбом занимает место в Blob и создаёт запросы VK/Blob/БД; импорт запускается только действием сотрудника с правом управления фотографиями для выбранного мероприятия.

Проверка в рабочей базе и перенос фотографий из пользовательского альбома при разработке не выполнялись: тесты используют подставные ответы VK, отдельную БД в памяти и не отправляют реальные файлы. Просмотр самого пользовательского альбома в браузере также заблокирован политикой безопасности инструмента; это не означает, что альбом закрыт или что рабочий сервер не сможет получить его через разрешённый VK API после подключения токена.
